# Per-build struct layouts

Authoritative memory layouts (field name / type / offset / size) dumped from each build's
own libMBIN serializer, so libMBIN's alignment rules are never reimplemented. These are the
data spine for the version-aware libMBIN (see `../RETRO_DESIGN.md`) and are consumed as-is by
NMS.retro.py's `gen_structs.py`.

| File | Build | How it was produced |
|------|-------|---------------------|
| `layout_rc1.json` | RC1 / launch (1.09.1), 525 structs | `MBINCompiler dumplayout` on this fork (native, uses `OffsetOf`/`SizeOf`) |
| `layout_1.24.json` | 1.24 Path Finder, 704 structs | `1.24.4` tag + `../patches/dumplayout-1.24.4.patch`, built and dumped |
| `layout_1.38.json` | 1.38 Atlas Rises, 890 structs | `1.38.0.2` tag + `../patches/dumplayout-1.38.0.2.patch`, built and dumped |

`layout_rc1.json` is regenerated by this fork's own `dumplayout`. The 1.24/1.38 files come
from the 2017 tags, which predate `OffsetOf`; the patches add a `--dumplayout` command that
captures each field's offset from `AppendToWriter` (depth-guarded to root fields). They are
vendored here as validated output; to reproduce:

```
git worktree add ../mbc-1.24.4 1.24.4
cd ../mbc-1.24.4 && git apply ../MBINCompiler.retro/patches/dumplayout-1.24.4.patch
# build (net452) and run:  MBINCompiler --dumplayout > layout_1.24.json
```

Format: flat `{ "StructName": { "size": <int>, "fields": [ {name,type,offset,size} ] } }`
(`layout_rc1.json` additionally carries a per-struct `guid`).
